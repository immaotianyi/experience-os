# EOS 是什么：一页读懂

> 面向第一次接触 Experience OS（EOS）的人。读完这页，你知道它是什么、为什么存在、怎么工作、怎么上手。

## ① 一句话定位

**EOS 把你和 AI 协作干活的经验，变成可审查、可复用的资产。**

AI 帮你干完活，过程就散了——下次遇到同类问题，还得重踩一遍坑。EOS 把这个过程记录下来：AI 做了什么、你批准了什么、哪些做法被验证有效，最后沉淀成 **Skill**（可复用技能），下次直接调用。

## ② 核心理念

**A. 经验比对话值钱** — 对话是一次性的，经验是复利的。EOS 不存你的代码和提示词，只存「做法」：什么情境、什么动作、什么结果。

**B. 没有批准，什么都不存** — EOS 的观察默认关闭。连接宿主要许可，捕获内容要许可，经验入库要人工审查。三道闸口都在你手里。

**C. 证据优先，不猜不装** — 每个连接状态都来自真实证据（MCP 握手、Hook 回执、配置回读），不因为「看起来装了」就算接通。

**D. 价值判断保留给人** — AI 负责整理草案，采纳或否决永远是你点按钮。EOS 治理的不是 AI，是「谁有权决定什么经验值得留」。

## ③ 怎么工作：五步主线

一个项目 = 一条经验主线，五步走完经验才算沉淀：

| 步骤 | 白话 | 发生了什么 |
|---|---|---|
| **① 保存节点** | AI 汇报了什么 | AI 在协作中的关键节点被记录（元数据，不含内容） |
| **② 确认收据** | 你批准捕获了什么 | 你显式批准后，这段经验片段才进入待审区 |
| **③ 人工审查** | 你拍板采纳或否决 | AI 整理成草案，你决定留不留 |
| **④ 结果验证** | 经验用对了没有 | 复用时验证效果，没用对的打回 |
| **⑤ 升级资产** | 沉淀为可复用 Skill | 验证通过的经验升为 stable，可搜索、可导出 MCP、可复用 |

## ④ 工作台名词白话表

| 界面上的词 | 人话 |
|---|---|
| **主线** | 现在做什么：项目页 + 总览页 |
| **管道** | 经验怎么变成资产：审查包 → 撞墙记录 → Skill 库 → 代码图 → 质量看板 |
| **连接** | 接入你的 AI 工具：Codex / Claude Code / Cursor / TRAE / VS Code |
| **治理** | 谁批准了什么：决策审计（全量可追溯）+ Vault 维护（资产存放地） |
| **审查包** | AI 整理好、等你拍板的经验草案 |
| **撞墙记录** | 卡壳/失败/踩坑的现场记录——经验提炼的原材料，撞墙不是坏事 |
| **Skill 库** | 已沉淀的可复用技能，出厂自带一组预设技能（审查后激活） |

| **Vault** | 经验资产的本地 Git 仓库，可备份可校验 |
| **交易（已搁置）** | 市场/营收属商业化方向，当前搁置，工具可用性优先 |

## ⑤ 菜单栏三灯

macOS 菜单栏的三个小灯显示 AI 工具的实时状态：

- **黄灯常亮** = 工作中（有宿主会话在活动）
- **红闪** = 阻塞（宿主卡住等待处理）
- **黄闪** = 权限请求（宿主在等你授权）
- **绿闪** = 已完成（会话静默结束）

## ⑥ 与 skill-central 的关系

**skill-central**（开源）解决「AI 编码约定写一次、处处可用」：Skill/Rule 分层治理 + MCP 暴露给所有 Agent。EOS 认同这个方向，并往前走了一步：

- skill-central 的 Skill 是**人写好放进去**的；EOS 的 Skill 主要**从真实协作中提炼**（撞墙 → 蒸馏 → 审查 → 验证）
- EOS 出厂预设技能包采用 skill-central 的 **Universal Skill v1** 格式（`skillcentral.dev/v1`），可互通
- 两者都通过 MCP 对外暴露；EOS 额外提供 stable Skill 的自包含 MCP Server 导出（stdio/SSE）

## ⑦ 上手三步

1. **连接工具** — 工作台「AI 工具连接」页，按证据逐个接入 Codex / Claude Code / Cursor / TRAE
2. **正常干活** — 菜单栏三灯实时反映状态，无需额外操作
3. **审查沉淀** — 「审查包」页处理 AI 整理的草案；「Skill 库」页审查出厂预设技能包
