# EOS Beta 测试说明

## 测试目标

EOS Beta 要验证的不是“页面能打开”，而是一个外部测试者能否独立完成以下闭环：

1. 启动隔离的本地 EOS 工作区；
2. 创建一个小型真实项目；
3. 明确同意保存一个工作节点；
4. 形成并人工确认一条 Experience Receipt；
5. 记录审查决策和真实结果；
6. 在满足证据门槛后升级经验资产；
7. 提交并下载 Beta 反馈。

## 数据边界

- 测试者的项目、工作节点、证据和经验默认留在其本地 Vault。
- EOS 不静默读取其他 AI 客户端、IDE、终端或浏览器。
- MCP Relay 在严格许可模式下只能捕获经过逐条批准的内容。
- 产品反馈与协作原文分离；反馈不应包含聊天全文、私人代码、API Key 或个人敏感数据。
- 同一浏览器使用稳定的匿名参与者 ID，以关联“初次印象”和“试用后”反馈；该 ID 不包含真实身份。

## 反馈回收

本地测试包中的反馈不会自动上传。测试者在“Beta 反馈”页面提交后，下载 JSON 文件，并通过邀请时约定的渠道交给测试组织者。

远端 Beta 服务只允许普通参与者提交反馈，不允许其枚举其他参与者的反馈。远端反馈导出仅对经过可信代理认证的 admin 开放。

## 验收标准

- macOS 和 Windows 启动脚本不会在服务尚未就绪时永久留下错误页面；
- 重复启动不会再创建第二个 4173 服务；
- 本地测试者能够下载反馈文件；
- 云端普通参与者不能读取或导出他人的反馈；
- 没有真实模型时，系统明确锁定 AI 草案，不用模拟输出冒充真实证据；
- 所有经验升级仍要求证据、人工审查和成功结果。
